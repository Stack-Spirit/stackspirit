# remote-exec streaming spike (S2)

This directory is the executable evidence for the `v2-s2-remote-exec-spike` card
in `VOWP-V2-PLAN.md` §13.3. It prototypes the transport that `v2-f1-remote-exec`
will implement in Rust, and nothing here is production code.

The design under test:

```text
laptop executor (this client)                 home (VPS)
  fake harness events ── JSON lines ──►  ingest.py
        ▲                                  │
        │   ack / lease.revoked / done     │  append-only log.jsonl
        └────────── JSON lines ────────────┘  seq assigned by the home
```

The client spools every event before sending it, keeps acks by event id and
re-sends every unacked event after a drop. The home has one writer, appends one
EventEnvelope-shaped line per new id, answers duplicates with the original
`seq`, truncates a torn final line, and pushes a lease notice when the lease is
taken over. See `../../docs/maintainers/v0.2-spikes/remote-exec.md` for the
findings and the recommendations to F1/F2.

## Run the hermetic tests

```sh
scripts/spikes/remote-exec/run.sh
```

The tests use a temporary `HOME`, `VOWP_HOME` and session directory, the fake SSH
proxy and a synthetic harness. They never start sshd, tmux, a real harness or
open a socket. The suite covers:

- three forced SSH cuts (one in the middle of a line), contiguous `seq` and no
  duplicates after replay;
- a killed client resuming from the disk spool;
- idempotency by event id, including a conflicting reuse of an id;
- lease rejection and a `lease.revoked` notice under 2 s;
- torn-tail truncation and a verifier that fails on a gap.

## Run the live measurements

```sh
scripts/spikes/remote-exec/run.sh --live \
  --out scripts/spikes/remote-exec/evidence/live-check.json
```

`--live` starts `/usr/sbin/sshd` as the current user on a free `127.0.0.1` port,
with temporary host/client keys and an `AllowUsers` line for that user. It runs
real `ssh` streams over loopback, then repeats the handshake/stream measurements
through a tiny TCP proxy that adds one-way delay (40 ms by default) to stand in
for a WAN. It never connects to an external host and never touches the VOWP home
or the user's tmux server. On a machine without sshd it prints `skipped` and
exits 0; the hermetic suite still runs.

| `tests/test_remote_exec.py` | hermetic unittest suite |
| `evidence/` | sanitized live evidence generated by `run.sh --live --out ...` |

## Protocol summary

Frames are one compact JSON object per line. The home -> client direction never
carries harness output, only acks and control notices.

| Frame | Direction | Fields |
|---|---|---|
| `hello` | client → home | `version`, `session`, `lease`, `client` |
| `hello.ack` | home → client | `session`, `last_seq`, `events` |
| `event` | client → home | `id`, `session`, `event` (the EventEnvelope body) |
| `ack` | home → client | `id`, `seq`, `duplicate` |
| `heartbeat` | client → home | `ts` |
| `heartbeat.ack` | home → client | `seq` |
| `lease.revoked` | home → client | `reason`, `by`, `at`, `last_seq` |
| `end` | client → home | `last_client_seq` |
| `done` | home → client | `events`, `last_seq`, `duplicates` |
| `error` | home → client | `code`, `message` |

`seq` is assigned only by the home, in append order, starting at 1. A replayed
id is acknowledged again with its original `seq`; a replayed id with different
event content is an error and is never appended.
