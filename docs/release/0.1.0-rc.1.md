## Part 1 — Release notes

VOWP is a local-first supervisor for AI coding agents. It drives stock Claude Code, opencode and
generic CLI harnesses through their headless interfaces, plans work as a job graph, keeps the
conversation in an append-only event log, verifies work by gate evidence, and ships changes through
guarded, reversible promotions. This is a release candidate: usable from source on Linux, exercised
end to end by the fresh-user container test, and exercised with fake model adapters by the dogfood
run — whose default scenario passes but whose verification and open defects are not finished.

### What is in it

- Seven crates: `vowp-protocol`, `vowp-store`, `vowp-graph`, `vowp-tmux`, `vowp-adapters`, `vowp-core`,
  `vowp-cli`. Every CLI command and its flags: [`docs/reference/cli.md`](../reference/cli.md).
- Adapters for Claude Code, opencode and a generic CLI.
- **Supervisor loops L1–L9, all on `main`:** L1 tick (reconcile, dispatch, gates, and step 7 of the
  tick — the single-writer merge queue), L2 worker, L3 independent verify and bounded fix loop, L4
  planner, L5 keeper, L6 automatic limit failover/probe-back, L7 inbox answer files, L8 watchdog and
  L9 schedules. n08d merged the L4–L8 loops as `356e185`; `8671ce4`, `afa6a04`, `ad163b0` and
  `0f78c1d` fixed live-run reconciliation, tick timing, harvested-run persistence and the final
  failover/rung issues. The merge queue is **not** an L3 step: it is step 7 of the L1 tick.
- Universal sessions: `session switch` between harness, model or node; capsules; export/import.
- Guarded `promote`, `rollback`, `releases`.
- `scripts/install.sh` / `uninstall.sh`, a systemd user unit and a cron watchdog.
- Docs (concepts, guides, security, troubleshooting, generated reference, design spec), a static site
  generator, the `examples/hello-vowp` demo and CI/release workflows.
- A hermetic fresh-user harness (`scripts/fresh-user/run.sh`) that extracts the documented commands
  from README/guides/example and runs them in a clean container.

Full list: [`CHANGELOG.md`](../../CHANGELOG.md).

### Install (from source)

```sh
cargo build --workspace
cargo run -q -p vowp-cli -- --version     # vowp 0.1.0-rc.1
cargo install --path crates/vowp-cli
```

No prebuilt archives, crates.io release or npm wrapper exist. Pushing a `v*` tag runs
`.github/workflows/release.yml`, which builds four targets and creates a **draft** GitHub release; that
workflow has never run.

### Docs follow-ups

Found by reading README.md, `docs/**`, CONTRIBUTING.md and the built binary's `--help`/`--version`
output. All are in files owned by docs/code jobs, so none were edited here.

1. **Stale version strings.** `README.md:80`, `CONTRIBUTING.md:21`, `docs/guides/quickstart.md:23` and
   `docs/guides/install.md:47` still say `vowp --version` prints `vowp 0.1.0-dev`; it prints
   `vowp 0.1.0-rc.1`. quickstart says "must print", so a reader following it thinks the install
   failed. (`docs/fresh-user/REPORT.md:177-178` records the old value as a historical observation.)
2. **`vowp version` format.** `docs/design/cli.md:136` documents `vowp 0.1.0 (<git sha>) schema 1`;
   the code prints `vowp <CARGO_PKG_VERSION> (<git>) schema <n>` and, in a fresh `$VOWP_HOME`, exits
   with `vowp home is not initialised; run \`vowp init\`` (observed). `vowp --version` works without a
   home.
3. **Skills path.** `docs/design/architecture.md:92` and `docs/design/plan.md:404` say skills install
   under `.agents/skills/`; `docs/design/cli.md` and the actual `vowp init` use `.claude/skills/`
   (Claude Code does not read `.agents/`; n09a and n11).
4. **Loop-row creation.** `docs/design/cli.md:45` says `vowp init` creates the loop rows;
   `docs/design/loops.md:68` and `docs/design/crates/vowp-core.md:296` say the supervisor does at
   `vowp up`/startup. The code creates them at startup; the design pages should agree.
5. **Design docs behind the code.** `docs/design/crates/vowp-core.md:193` still sketches the deferred
   `ClaudeTranscriptImporter` as if it were part of the shipped `session watch` path.
6. **Stale stub comments.** `crates/vowp-cli/src/cmd/mod.rs:3-5` and `crates/vowp-cli/src/cli.rs:6-8`
   still say commands are explicit `NotImplemented` stubs; the v0.1 CLI has no command stubs left.
7. **`vowp job show --gates`.** It prints only recorded gate results, so the section is empty before
   the first run (`crates/vowp-cli/src/cmd/job.rs:380-398`). The docs now describe that behaviour;
   printing the configured gates with a "not run" marker would be the nicer fix.
8. **Fresh-user harness polish.** `scripts/fresh-user/extract.py`: assert the documented exact
   `11 files written` count, assert `vowp status` prints `supervisor: running`, and fail when a new
   README quickstart block is not selected. `docs/fresh-user/REPORT.md:180` should add the
   `warn supervisor not running` line to its "what the docs got right" table.
9. **Counts are current.** `docs/reference/cli.md` has 25 `###` command headings: the 24 visible
   commands in `vowp --help` plus the hidden `vowp __window`, which is also documented. The earlier
   "63/64 command sections" count is obsolete.

Items 1–5 are documentation drift; item 6 is a comment-only code cleanup; items 7–8 are follow-ups
from the fresh-user verifier, not missing v0.1 behaviour.
