## Part 1 — Release notes

VOWP is a local-first supervisor for AI coding agents. It drives stock Claude Code, opencode and generic
CLI harnesses through their headless interfaces, plans work as a job graph, keeps the conversation in an
append-only event log, verifies work by gate evidence, and ships changes through guarded, reversible
promotions. This is a release candidate: usable from source on Linux, not yet proven by an end-to-end
run of the real binary (see Part 2).

### What is in it

- Seven crates: `vowp-protocol`, `vowp-store`, `vowp-graph`, `vowp-tmux`, `vowp-adapters`, `vowp-core`,
  `vowp-cli`. Every CLI command and its flags: [`docs/reference/cli.md`](../reference/cli.md).
- Adapters for Claude Code, opencode and a generic CLI.
- Supervisor loops L1 (tick), L2 (worker), L3 (verify, merge queue) and L9 (schedules).
- Universal sessions: `session switch` between harness, model or node; capsules; export/import.
- Guarded `promote`, `rollback`, `releases`.
- `scripts/install.sh` / `uninstall.sh`, a systemd user unit and a cron watchdog.
- Docs (concepts, guides, security, troubleshooting, generated reference, design spec), a static site
  generator, the `examples/hello-vowp` demo and CI/release workflows.

Full list: [`CHANGELOG.md`](../../CHANGELOG.md).

### Install (from source)

```sh
cargo build --workspace
cargo run -q -p vowp-cli -- --version     # vowp 0.1.0-rc.1
cargo install --path crates/vowp-cli
```

No prebuilt archives, crates.io release or npm wrapper exist. Pushing a `v*` tag runs
`.github/workflows/release.yml`, which builds four targets and creates a **draft** GitHub release; that
workflow has never run.

### Not included

- **L4–L8 on `main`** (planner and keeper loops, automatic failover/probe-back, inbox answer files, the
  watchdog loop) are job n08d, unmerged at the time of writing.
- Remote-node probe during a cross-node switch (a documented `TODO`).
- IANA time zones, the Claude Code transcript importer used by the adapter, schedule anchoring to creation
  time, and a caller-chosen Claude session id on the first turn after a `session switch` (a fresh session
  does get a generated uuid-v4). Details in the CHANGELOG "Known limitations".
