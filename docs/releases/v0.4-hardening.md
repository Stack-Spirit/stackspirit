# v0.4 — phase-4 hardening release evidence

Status: current. **Evidence record; not a release announcement.** This page records the security
review checklist and the rollback drill required by
[`docs/design/v0.4/hardening.md`](../design/v0.4/hardening.md) §8.2 and §8.4. The phase-4 code is
merged in this tree. The seven-day soak (§8.3) has **not** been run; it remains an owner question and
no soak number is claimed here. No tag, release date or deploy is promised.

The code under review is the phase-4 tree at commit `37f9b36` (`docs: land the phase-4 hardening
documentation`). The rollback drill used the pre-phase binary built from `7a47edb`
(`docs: land the phase-4 hardening design`, the last commit before the phase-4 code) and the current
binary built from the job tree. Every drill command ran against temporary directories under
`/tmp/opencode/v4-4g-drill`; no real home, live supervisor, tmux server, service manager, sudo
command or network endpoint was touched.

### Security review findings

- **One item is not a runtime enforcement.** §8.2 item 5's shared-checkout refusal is documented as
  unsupported in the tree, not enforced when a run starts. The state-directory owner/mode and root
  checks are enforced. This is the only §8.2 item marked *not met as written*; it is an owner
  question in the report, not a waiver.
- The TLS proxy is trusted by design. Its access logs are the owner's configuration; VOWP's listener
  logs no frame body. A compromised proxy is a home compromise, and the owner action is to rotate the
  affected surface tokens and revoke the node.
- The changed-fingerprint confirmation command named by the design (`vowp agent trust`) is not
  shipped. The shipped recovery is re-enrollment. The refusal is the security-relevant behavior and
  is tested.

## 2. Rollback drill (§8.4)

**Environment.** The drill ran on 2026-11-16 UTC on Linux 6.8 x86_64 with `rustc 1.99.1`
(2026-10-13). `VOWP_OLD` is the pre-phase binary, built in a detached temporary worktree at
`7a47edb` (`docs: land the phase-4 hardening design`) with a private `CARGO_TARGET_DIR`; it reports
`vowp 0.3.0` (SHA-256 `78b1a2fb…b880`). `VOWP_NEW` is the current binary built from the job tree
at `37f9b36` (SHA-256 `7a41214f…ec57`). Every path below is under the temporary drill root
`$DRILL=/tmp/opencode/v4-4g-drill`; `HOME`, `XDG_CONFIG_HOME`, `VOWP_AGENT_HOME` and
`TMUX_TMPDIR` are under it, `TMUX`/`TMUX_PANE` are unset, and no real home, live supervisor,
tmux server, launchd, systemctl or `sudo` was used. The service-manager commands went to a fake
`systemctl` that only records its argv and returns success.

### Step 1 — stop the agent service and keep the spool

```sh
export HOME=$DRILL/service-drill/home
export XDG_CONFIG_HOME=$DRILL/service-drill/xdg
export VOWP_AGENT_HOME=$DRILL/service-drill/state
export PATH=$DRILL/fakebin:$PATH FAKE_MANAGER_LOG=$DRILL/logs/service-manager.log

$VOWP_NEW --json agent service install --print
test ! -e "$XDG_CONFIG_HOME/systemd/user/vowp-agent.service"
$VOWP_NEW --json agent service install
stat -c '%a %U %n' "$XDG_CONFIG_HOME/systemd/user/vowp-agent.service"
$VOWP_NEW --json agent service status

mkdir -p "$VOWP_AGENT_HOME/bridge/drill/spool"
printf '{"seq":1,"event":"kept for inspection"}\n' \
  > "$VOWP_AGENT_HOME/bridge/drill/spool/pending.jsonl"
$VOWP_NEW --json agent service uninstall --yes
```

**Result:** `--print` wrote no file. `install` wrote
`$XDG_CONFIG_HOME/systemd/user/vowp-agent.service` at mode 0600, owned by the drill uid, and
called no manager. `status` read the fake manager and reported `loaded: true`, `last_exit: 0`.
`uninstall --yes` issued `systemctl --user disable --now vowp-agent.service` and
`systemctl --user daemon-reload`, removed the unit, and kept the 40-byte spool file and the state
directory. `ps -eo pid,args | grep '[v]owp agent run'` showed no agent process. The drain itself
(flush, `SurfaceDetach`, lease release, `connection = stopped`, kept spool and launchd marker) is
proved by `agent_service_drain_flushes_the_spool_and_releases_the_lease`.

### Step 2 — `vowp down --drain`

```sh
export HOME=$DRILL/srv-env XDG_CONFIG_HOME=$DRILL/srv-env/xdg
export TMUX_TMPDIR=$DRILL/srv-tmux
cd $DRILL/srv-repo
$VOWP_NEW --home $DRILL/srv-home --project $DRILL/srv-repo up --no-tmux --foreground &
ss -ltn 'sport = :18743'
$VOWP_NEW --home $DRILL/srv-home --project $DRILL/srv-repo status --json
$VOWP_NEW --home $DRILL/srv-home --project $DRILL/srv-repo down --drain --json
wait
```

**Result:** the supervisor was pid 1911435 and the WSS listener was bound at
`127.0.0.1:18743`; `status` reported `slots.busy = 0` of 6 and no running jobs. `down --drain`
returned `{"running":false,"pid":1911435,"mode":"down"}`, the supervisor exited 0, the lock and
drain marker were removed, and the listener was gone. No active run or gate was signalled. The
active-run variant is `down_drain_and_up_replace_handoff` in
[`crates/vowp-cli/tests/up.rs`](../../crates/vowp-cli/tests/up.rs): it proves a running harness is
allowed to finish, a job inserted after the drain marker is not admitted, and the drained
supervisor exits 0.

### Step 3 — node revoke

```sh
$VOWP_NEW --home $DRILL/srv-home --project $DRILL/srv-repo node enroll mac-drill --json
$VOWP_NEW --home $DRILL/srv-home --project $DRILL/srv-repo node revoke mac-drill --yes --json
$VOWP_NEW --home $DRILL/srv-home --project $DRILL/srv-repo node show mac-drill --json
```

**Result:** the new node was `kind: agent`, `status: pending`, `presence: offline`; revoke returned
`{"node":"mac-drill","status":"revoked","credentials_revoked":0}` (the drill node was pending, so
it held no credential); `node show` then reported `status: revoked`, `presence: revoked`. The
connected-node path is `gateway.rs` → `dispatch::fence_node`; `fence_node` → `lose` marks the
assignment `Lost`, ends the run and releases its lease, and `gateway_revoke_marks_and_closes`
proves the `Revoked` frame, node card and credential. The fence/lost path is also proved by
`cancelled_job_sends_cancel_run_and_fences_the_assignment` and
`run_lost_after_an_expired_lease_marks_the_assignment_lost`. No live node connection was opened
here.

### Step 4 — WSS off and offload off

```sh
# [ingress.wss].enabled = false in $DRILL/srv-home/config.toml
# [offload].enabled = false in $DRILL/srv-repo/vowp.toml
$VOWP_NEW --home $DRILL/srv-home --project $DRILL/srv-repo offload policy --json
$VOWP_NEW --home $DRILL/srv-home --project $DRILL/srv-repo up --no-tmux --foreground &

$VOWP_NEW --home $DRILL/srv-home --project $DRILL/srv-repo down --json
```

**Result:** the project policy changed from `enabled: true` to `enabled: false` with
`result_transport: push`; with the ingress table disabled the second supervisor started without
binding `127.0.0.1:18743`, and `down` stopped it with exit 0. The proxy side is the owner's; the
loopback listener was stopped with the supervisor in step 2. The same off-by-default behavior is
asserted by `up_does_not_start_the_wss_gateway_when_ingress_is_disabled` in
[`crates/vowp-cli/tests/up.rs`](../../crates/vowp-cli/tests/up.rs).

**Result:** the pre-phase `init` created a schema-v6 home (`user_version = 6`) with one node, two

`user_version = 6` with the same table counts; `projects/drill/project.db` `user_version = 2`,
`jobs = 1`, `loops = 9`. The source home hash and the backup file hash are different because the
backup uses SQLite's online copy, not a byte copy; the manifest is the integrity contract.

## 5. Confirmed deviations

These are the shipped deviations already recorded in
[`docs/design/v0.4/hardening.md`](../design/v0.4/hardening.md#build-status-and-known-deviations);
the review relies on that statement rather than presenting the design target as shipped:

- `vowp agent trust` (the owner confirmation for a changed system-mode fingerprint) is not
  implemented. A changed fingerprint is refused; re-enrollment is the recovery.
- A group-writable shared checkout is documented as unsupported; it is not a runtime refusal. The
  state-directory owner/mode and root checks are enforced.
- A queued rotation whose replacement token expired before delivery is still delivered; the home
  refuses the expired token on first use and the owner re-pairs.
- `agent service status` and `capacity history` have no command-specific `--json`; the global
  `--json` flag prints their documents.
- `CapacityHistory` carries `until` and `retention_secs` beyond the original design example.
